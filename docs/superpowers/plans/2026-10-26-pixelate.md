# Pixelate tool Implementation Plan

> Status: executed 2026-10-26 on branch feature/pixelate (inline). Rulings: `next_marker_number` removed (the provisional shape now joins the item list); `draw_shape` made private; sample screenshot got fine title detail so pixelation shows in the GUI run.

**Goal:** A Pixelate tool (P): drag a rectangle; the screenshot inside becomes coarse blocks.

**Architecture:** New `Shape::Pixelate { rect, width }`. Rendering samples the
*original* screenshot (passed to `draw_items` as `base`), averaging each block
of an image-aligned grid clipped to the rectangle. Draw order in `draw_items`:
pixelations, then highlights, then everything else. The canvas appends the
provisional shape to a copy of the item list, so it follows the same layering
and marker numbering.

**Spec:** design doc Roadmap item 3, narrowed with the user on 2026-10-26:
pixelate only, no blur.

## Agreed details

- Block size from width: Thin 6, Medium 10, Thick 16 image px. Color ignored.
- Under all other annotations; samples only the screenshot.
- Resizes/moves like a redaction. Shortcut P, button "Pixelate" after Highlight;
  tooltip and README: not safe for sensitive data, use Redact.

## Review Focus

1. Pixelate over a redaction must not reveal or blur the redaction (drawn under it).
2. Rect partly outside the image: no panic, clipped.
3. Zero-size / sub-pixel rect: nothing drawn, no panic.
4. Export equals canvas (same draw_items).
5. Width buttons on a selected pixelation change block size, one undo step.
