# Text Size Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Thin/Medium/Thick buttons set the font size of text labels (12/16/28 px), for new labels, the selected label and the open text editor.

**Architecture:** `Shape::Text` gets a `width: Width` field. `Width` maps to a font size and a padding. Everything that measures or draws text (`TextMeasure`, `geometry::bounds`, `render`, the `text_edit` overlay) gets the size from the label instead of the constant `TEXT_FONT_PX`. The editor treats text width like color.

**Tech Stack:** Rust, GTK4/relm4, cairo/pango, kurbo.

**Spec:** `docs/superpowers/specs/2026-11-17-text-size-design.md`

## Global Constraints

- Font size: Thin 12 px, Medium 16 px, Thick 28 px (`Width::font_px`).
- Padding = `font_px * 6 / 16` (4.5 / 6 / 10.5 px). The border stays `TEXT_BORDER` = 2 px.
- `TEXT_FONT_PX` and `TEXT_PADDING` are removed. All sizes come from `Width`.
- Changing a selected label's width is one undo step. Changing nothing makes no step.
- Commits: no co-author or AI mention (user rule).
- Before handing over: `cargo test`, `cargo clippy --all-targets -- -D warnings`, and a headless check with `tests/gui/` (see the memory rule "verify UI headless").

## Review Focus

1. Resizing while typing a **new** label: the editor box, the font and the padding all change at once, and the committed label sits exactly where the editor box was (no jump). → Task 3, GUI check.
2. Re-editing a Thick label at view scale ≠ 1 (a large screenshot that is fitted into the window): the editor overlay matches the drawn label. → Task 3, `placement` test at scale 0.5 for Thick, plus the GUI check.
3. Selecting a Thin label, then drawing a box: the box is Thin, because `adopt_selected_style` takes the width over. → Task 2 test `selecting_text_adopts_its_width`.
4. Clicking width while a new label is open must not resize some other previously selected item. `start_new` already clears the selection. → Task 2 test `width_click_without_selection_changes_no_item`.
5. Hit test and selection handles of a Thick label cover the whole larger box. → Task 1 test `text_bounds_grow_with_width`.

### Task 3: The text editor overlay follows the width, live

**Files:**
- Modify: `src/text_edit.rs` (placement, editor_size, editor_css, TextEditor)
- Modify: `src/app.rs` (`SetColor` / `SetWidth` handlers)
- Modify: `docs/superpowers/specs/2026-11-17-text-size-design.md` (Status → implemented), `docs/superpowers/specs/2026-10-26-annotshot-design.md` (Implementation notes: one line on text size), `docs/superpowers/backlog.md` (task 2 → erledigt)

**Interfaces:**
- Consumes: `Width::font_px`, `Width::text_padding`, `Editor::text_of -> (Point, String, Style)`.
- Produces:
  - `placement(origin_widget: Point, scale: f64, width: Width) -> Placement`
  - `editor_size(text: Size, scale: f64, width: Width) -> (i32, i32)`. The empty-text minimum width is `font_px / 2`.
  - `editor_css(scale: f64, style: Style) -> String`
  - `TextEditor::open(&self, origin_widget: Point, scale: f64, style: Style, initial: &str)`
  - `TextEditor::set_style(&self, style: Style)` replaces `set_color`: it reloads the CSS, re-applies the inner margins, recomputes the size request from the current buffer text, and gives the focus back.
  - `TextEditor` keeps the current `Width` in an `Rc<Cell<Width>>`, shared with the buffer-changed closure (like `scale`), which measures with `width.font_px()`.

- [ ] **Step 1: Write the failing tests** (in `text_edit.rs` tests, adapting the existing ones to the new signatures with `Width::Medium` and `Style { color, width: Width::Medium }`)

```rust
#[test]
fn placement_follows_width() {
    let p = placement(Point::new(10., 10.), 1.0, Width::Thick);
    assert_eq!(p.font_px, 28.0);
    assert!((p.border + p.inner as f64 - Width::Thick.text_padding()).abs() <= 0.5, "{p:?}");
    let half = placement(Point::new(10., 10.), 0.5, Width::Thick);
    assert_eq!(half.font_px, 14.0);
}

#[test]
fn editor_size_follows_width() {
    // 50×19 text, Thick: (50 + 21) × (19 + 21) → (71, 40) at scale 1.
    assert_eq!(editor_size(kurbo::Size::new(50., 19.), 1.0, Width::Thick), (71, 40));
}

#[test]
fn css_uses_width_font_size() {
    let css = editor_css(1.0, Style { color: Color::Blue, width: Width::Thin });
    assert!(css.contains("font-size: 12.000px"), "{css}");
}
```
`inner` is an i32 TextView margin, so a fractional padding (10.5, 4.5) is matched to within 0.5 px only. The existing Medium assertions stay exact.
