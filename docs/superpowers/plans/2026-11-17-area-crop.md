# Select Area: Copy or Crop — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new **Area** tool (C) lets the user drag a rectangle on the image. Ctrl+C then copies only that area. Enter or the Crop button crops the image to it, the annotations stay editable, and the crop can be undone.

**Architecture:**
- The base image moves from `CanvasState` into `Editor`, so the editor can clamp the area to it and swap it on undo.
- `History` becomes generic over its snapshot type. A snapshot may carry a crop side: the image, the crop area, and which side of the crop it is.
- `export::crop` cuts a surface.
- The canvas draws the area: the outside is dimmed and the area gets a dashed border with handles.
- The app adds the tool button, the C, Enter and Escape keys, a Crop button that replaces colors and widths, and area-aware copying.

**Tech Stack:** Rust, GTK4/libadwaita/relm4, cairo, kurbo.

**Spec:** `docs/superpowers/specs/2026-11-17-area-crop-design.md`

## Global Constraints

- Tool: `Tool::Area`, shortcut **C** (no modifiers, Shift allowed like the other tool letters). The toggle button is labelled `Area` with tooltip `Select area (C)` and sits last in the tool column, after Redact.
- The area is in image coordinates. Edges are rounded to whole pixels and clamped to `0..width`, `0..height`. An area narrower or lower than `MIN_SIZE` is removed.
- The area exists only while the tool is Area. Leaving the tool, Escape, ordinary undo/redo, paste (`reset`) and rotation remove it. It is never in `items`, never in history, never in exports, and never marks the document dirty.
- **Crop** button: label `Crop`, tooltip `Crop to area (Enter)`. It shows in the side panel instead of the color and width buttons while the tool is Area, and is sensitive only when `Editor::can_crop()`. `can_crop()` is false when there is no area, or when the area equals the whole image.
- Copy toast: `Copied area` with an area, `Copied` without one (unchanged).
- Crop:
  - Items shift by `-area.origin()`.
  - Items whose `geometry::bounds` lie entirely outside the new image are dropped. Touching the border counts as inside.
  - The selection clears and the tool returns to the one active before Area.
  - The document becomes dirty.
  - The crop is one undo step.
- Undo of a crop restores the old image and items, sets the tool to Area and restores the area. Redo of a crop ends as a crop does: area gone, the tool from before Area active.
- Rotation is unchanged (merge/delete dialog, history cleared).
- Commits: no co-author trailer and no Claude/AI mention (user rule).
- Before handing over: `cargo test`, `cargo clippy --all-targets -- -D warnings`, the headless check in `tests/gui/`.

## Review Focus

1. **Enter right after clicking the Area button.** That button keeps keyboard focus, and pressing Enter must crop, not re-activate the button. → Task 4 puts the window key controller in the capture phase. The GUI check in Task 6 clicks the button, drags, and presses Enter.
2. **Undo a crop, nudge the area, crop again, undo twice.** This must give back the original image and items, and redo must be empty after the second crop. → Task 3 test `recrop_after_undo_then_undo_twice_restores_original`.
3. **Crop with a text label still being typed.** The label is committed first and shifts with the crop. → Task 4: `AppMsg::Crop` calls `commit_text_if_open()` first. Covered by the Task 6 GUI check.
4. **A drag that starts or ends beyond the image edge, or a move pushed past it.** The area stays inside the image at full size, and a move does not shrink it. → Task 2 tests `area_is_clamped_and_snapped` and `moving_area_stops_at_image_edge`.
5. **Area, then Crop, starting from the Highlight tool.** The tool returns to Highlight and Highlight keeps its own color, because the color swap in `set_tool` still pairs up. → Task 3 test `crop_returns_to_previous_tool_with_its_color`.

### Task 2: The Area tool in the editor

**Files:**
- Modify: `src/editor.rs` (Tool, fields, set_tool, hover, press/drag/release, tests)
- Modify: `src/canvas.rs` (`cursor_for` gets a `Tool::Area` arm that returns `"crosshair"`, plus the test line)

**Interfaces:**
- Consumes: `Editor::image()` (Task 1).
- Produces:
  - `Tool::Area` (new variant, last).
  - Editor fields: `area: Option<Rect>` and `tool_before_area: Tool`.
  - `pub fn area(&self) -> Option<Rect>`
  - `pub fn clear_area(&mut self) -> bool`, which returns true if an area was removed.
  - `pub fn can_crop(&self) -> bool`
  - New `Drag` variants for the area: new, move, handle.
  - `fn image_rect(&self) -> Option<Rect>`, which is `(0,0,w,h)` of the image.
  - `fn snap_area(r: Rect, bounds: Rect) -> Option<Rect>`. It returns the edges rounded and intersected with `bounds`, or `None` if `width < MIN_SIZE || height < MIN_SIZE`.

Behaviour:
- `set_tool(Area)` from another tool stores `tool_before_area` and clears `selected`. Leaving Area sets `area = None`. Keep the existing Highlight color swap.
- With the Area tool, `press` never grabs or selects items:
  - On a handle or side of the area (use `grab_at` on `Shape::Redact { rect: area, .. }` with the same sizes as `grab_selected`), it drags that handle with `drag_handle`.
  - Inside the area, it moves the area.
  - Elsewhere, it starts a new area.
- `drag_to` re-snaps the area on every step.
  - A move translates by the delta and then clamps the offset so that the whole rectangle stays inside the image. The size is kept.
  - A new drag or a handle drag snaps to the bounds.
  - While the area is below `MIN_SIZE` it is `None`, so a plain click removes it.
- `hover` with the Area tool:
  - a handle or side of the area gives `Hover::Handle(h)`;
  - inside the area gives `Hover::Item` (move cursor);
  - anything else gives `Hover::Nothing`.
- The area never touches history or `dirty`.

### Task 3: Crop with undo

**Files:**
- Modify: `src/history.rs` (generic)
- Modify: `src/export.rs` (`crop`)
- Modify: `src/editor.rs` (snapshot type, `crop`, `undo`, `redo`, tests)

**Interfaces:**
- `History<T>`:
  - `record(&mut self, before: T)`
  - `undo(&mut self, current: impl FnOnce(&T) -> T) -> Option<T>`: pops the step, pushes `current(&popped)` onto redo, and returns the popped step.
  - `redo` mirrors `undo`.
  - `can_undo`, `can_redo` and `clear` are unchanged.
  - Update the existing history tests to `History<Vec<Item>>` with `|_| current`.
- `export::crop(src: &ImageSurface, area: Rect) -> ImageSurface`: a new ARGB32 surface of `area.width() × area.height()` holding those pixels unchanged (Nearest filter, as in `rotate`). `area` has whole-pixel edges inside `src`.
- In `editor.rs` (private):

```rust
struct Snapshot { items: Vec<Item>, crop: Option<CropSide> }
/// One side of a crop step. `before_crop`: restoring it brings back the
/// uncropped image with the Area tool and `area`; otherwise the cropped image
/// with the tool from before Area and no area.
struct CropSide { image: ImageSurface, area: Rect, before_crop: bool }
```

- `history: History<Snapshot>`. `commit_from(before: Vec<Item>)` records `Snapshot { items: before, crop: None }`.
- `pub fn crop(&mut self, m: &dyn TextMeasure) -> bool`. It does nothing and returns false unless `can_crop()`. Otherwise:
  - record `Snapshot { items, crop: Some(CropSide { image: old, area, before_crop: true }) }`;
  - set the image to `export::crop(old, area)`;
  - shift and drop items as in Global Constraints;
  - `selected = None`, `set_tool(tool_before_area)` (which clears the area), `dirty = true`.
- `undo()`/`redo()` keep their signatures.
  - The counterpart pushed is `Snapshot { items: current, crop: popped.crop.map(|c| CropSide { image: current image, area: c.area, before_crop: !c.before_crop }) }`.
  - Applying a snapshot with `crop: Some(c)` sets the image, then:
    - if `c.before_crop`: `set_tool(Tool::Area)` (only if not already Area) and `area = Some(c.area)`;
    - otherwise: if the tool is Area, `set_tool(tool_before_area)`.
  - Applying a snapshot with `crop: None` sets `area = None` (spec: ordinary undo removes the area).
  - Then the existing `apply` runs: items, stale selection, dirty.

- Set the window key controller to `gtk::PropagationPhase::Capture`, so Enter reaches the app even when a toolbar button has focus. `key_message` already lets everything through to an open text editor except save, and to dialogs nothing at all. Check that Escape in the open text editor still commits the text (the editor's own handler) and does not become `ClearArea`.
- Side panel: the colour swatches, the separator and the width buttons get `#[watch] set_visible: model.tool != Tool::Area`. A `Crop` button gets `#[watch] set_visible: model.tool == Tool::Area` and `#[watch] set_sensitive: model.can_crop`.
- `canvas::draw`: when `ed.area()` is `Some(a)`, after the items and inside the image clip, fill the image rectangle minus `a` with `rgba(0,0,0,0.45)` using the even-odd fill rule. Then, outside the clip, call `draw_selection` for the area.
