# Rotate Image Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two header-bar buttons and Ctrl+R / Ctrl+Shift+R turn the image by 90°. Existing annotations are first merged into the image or deleted, as the user picks in a dialog.

**Architecture:** A pure helper `export::rotate` returns a turned copy of a cairo surface. `Editor::clear_for_rotation` drops items, selection and history and marks the document dirty. `AppModel` wires buttons, shortcuts and a three-way `adw::AlertDialog`. When merging, `export::flatten` builds the new base image before turning it. The view and the pixelate cache need no change: both follow the new surface on their own.

**Tech Stack:** Rust, GTK4/libadwaita/relm4, cairo.

**Spec:** `docs/superpowers/specs/2026-11-17-rotate-design.md`

## Global Constraints

- Ctrl+R turns right (clockwise), Ctrl+Shift+R turns left. `R` without Ctrl stays Box.
- Buttons go after Undo/Redo (`pack_start`): icons `object-rotate-left-symbolic` / `object-rotate-right-symbolic`, tooltips `Rotate left (Ctrl+Shift+R)` / `Rotate right (Ctrl+R)`. They are enabled when `has_image` is true.
- Dialog: heading `Rotate image?`; body `The annotations can be merged into the image, where they can no longer be edited, or deleted.`; responses `cancel` "Cancel" (close response), `delete` "Delete annotations" (destructive), `merge` "Merge into image" (suggested, default).
- After a rotation: no items, no selection, empty undo/redo, dirty. There is no undo for a rotation.
- A turn is an exact 90° pixel permutation: width and height swap, and no pixel value changes.
- Commits: no co-author trailer and no Claude/AI mention (user rule).
- Before handing over: `cargo test`, `cargo clippy --all-targets -- -D warnings`, and the headless check in `tests/gui/`.

## Review Focus

1. Clicking a rotate button while typing a new text label commits the label first, so the dialog appears. Ctrl+R while typing does nothing, because keys go to the text field. → Task 2 (`key_message` test) and the Task 3 GUI check.
2. Ctrl+R while another dialog is showing (save, unsaved changes, or the rotate dialog itself) does nothing. → Task 2: `Rotate` is ignored while `busy`. The existing `open_dialog_blocks_all_shortcuts` test covers the key path.
3. Merging pixelate and highlight annotations: the merged result equals what Save would write, because it uses the same `flatten`. → Task 2 uses `flatten`. The Task 3 GUI check includes a pixelate area.
4. Rotating after saving: the title shows unsaved changes, and closing asks before quitting. → Task 1 test `clear_for_rotation_empties_and_dirties`.
5. A tall image turned to landscape, or the other way round, fits the window again with no stale letterbox. → Task 3 GUI check (`view()` re-fits on every draw).

### Task 1: Turn a surface; editor state after a turn

**Files:**
- Modify: `src/export.rs` (new `Turn`, `rotate`, tests)

**Interfaces:**

- Produces: `pub fn rotate(src: &ImageSurface, turn: Turn) -> ImageSurface` in `export.rs`. The result is a new ARGB32 surface of size `src.height() × src.width()`.

- [ ] **Step 3: Implement**

`rotate`: create the output surface at the swapped size. Then set the cairo transform: for `Right`, `translate(src.height(), 0)` then `rotate(PI/2)`; for `Left`, `translate(0, src.width())` then `rotate(-PI/2)`. Set the source surface with `Filter::Nearest` and paint, then flush.

`clear_for_rotation`: clear `items`, `selected`, `history` and `drag` (to `Drag::None`), and set `dirty = true`. Keep `tool`, `style` and `next_id`. The doc comment says why history goes: old steps refer to the unrotated image.

- [ ] **Step 3: Implement**

- `files.rs`: `rotate_dialog()` uses the exact copy from Global Constraints, built the same way as `unsaved_dialog`. Add `RotateChoice` with `from_response`.
- `shortcut()`: in the `CONTROL|SHIFT` branch, `s` → `SaveAs` and `r` → `Rotate(Left)`. In the `CONTROL` branch, `r` → `Rotate(Right)`.
- Header bar: add two `pack_start` buttons after Redo, following Global Constraints. They are `#[watch] set_sensitive: model.has_image` and send `AppMsg::Rotate(Turn::Left/Right)`.
- `update`:
  - `AppMsg::Rotate(turn) if !self.busy`: call `commit_text_if_open()`. With no image, do nothing. With an empty `editor.items`, call `self.rotate(turn, false)`. Otherwise set `busy = true` and show `rotate_dialog()` with `choose_future`, which sends `RotateConfirmed(turn, RotateChoice::from_response(..))`. When `busy`, `Rotate` does nothing.
  - `AppMsg::RotateConfirmed(turn, choice)`: set `busy = false`. `Merge` calls `self.rotate(turn, true)`, `Delete` calls `self.rotate(turn, false)`, and `Cancel` does nothing.
- `fn rotate(&mut self, turn: Turn, merge: bool)` on `AppModel`: when `merge`, set `image = export::flatten(&image, &items, &measure)`. Then set `image = export::rotate(&image, turn)`, call `editor.clear_for_rotation()` and set `editing = None`. `sync()` at the end of `update` repaints and refreshes undo, redo and dirty.
- `README.md` shortcuts table: add `| Ctrl+R / Ctrl+Shift+R | Rotate right / left |` after the undo row.
